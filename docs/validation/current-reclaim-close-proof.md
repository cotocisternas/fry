# Current-file reclamation closure-proof audit

Status: repair, focused regression checks, full repository PostgreSQL race tests and vet passed on 2026-10-17.

The sealed-file and automatic-rotation audit exposed older current-file reclamation paths that did not preserve proof of file closure. `rewriteHot` ignored snapshot and deferred successor close errors, ignored current-store close errors after uncertain publication, and set only ordinary frozen state for some other close failures. `LocalMember.Close` evaluated root-lock closure even when byte-store closure failed, then returned nil on later calls because it had marked the member closed.

Those paths could allow recovery or shutdown to release ownership and reclaim a file despite an unresolved descriptor lifetime. They need the same atomic closure-debt barrier already used by sealed reads and rotation: propagate the close failure as uncertainty, retain the relevant file/charge obligations, and refuse root release and successful repeated shutdown until closure has actually been established. Process exit and subsequent trusted recovery remain distinct from a successful in-process close.

The tests perform the real descriptor close successfully, then inject loss of its proof. This deliberately avoids leaking real handles and does not claim an observed operating-system close failure. They cover current snapshots, unpublished successors, published predecessors, the temporary successor close before restoring its full budget, local shutdown and authenticated owner shutdown. Expected retained charges depend on the cut: a predecessor already durably unlinked before a later failure stays removed; the new uncertainty does not fabricate completion for a still-open resource.

The repair propagates snapshot and store closure failures through the existing atomic closure-debt barrier. The rewrite's named return joins deferred successor-close errors with any primary failure. Terminal member shutdown closes the byte store first and releases the root only on success; repeated calls check uncertainty before the closed shortcut. An authenticated owner may close its database connection while retaining an unclosed durable owner generation, so a new session cannot manufacture successful shutdown from a lost connection.

Focused run `42340` failed because the core test helper expected `receiptstore.ErrBusy` for a duplicate root open; the actual refusal correctly used `hotstore.ErrBusy`. The helper now checks that exact storage sentinel. No production change was needed for this assertion correction. The independent shutdown tests passed in that initial run. Evidence: `/tmp/fry-current-close-proof-focused.log`.

Final combined focused race run `80570` passed, receiptstore `26.224s` (`/tmp/fry-current-close-proof-final.log`). It includes six current-rewrite close cuts, independent local/remote terminal closure tests, and the existing sealed-read, explicit/automatic rotation guards. Tests verify preserved primary errors, repeated uncertainty, independently probed root flock retention, refusal of a second open without file/staging mutation, correct per-phase physical charge/target state and durable owner-generation rejection even after test-only release of the known-closed resource. Independent source and test review found no remaining blocker in this repair's scope.

Full repository PostgreSQL race run `98628` passed against PostgreSQL `18.6`, including receiptstore `96.847s` and SMTP `42.295s` (`/tmp/fry-current-close-proof-race.log`). Vet also passed without diagnostics (`/tmp/fry-current-close-proof-vet.log`). These results cover the repaired code across the repository; the fault tests remain synthetic proof-loss simulations, not observed operating-system close failures or evidence of production crash recovery.
