# Freeze the initial ingestion placement catalog

The first sharded implementation uses a fixed catalog of independent replica pairs, selected for new work by a versioned hash of the server-generated attempt ID. The attempt ID exists before receipt preparation, so this distributes a single inbox's burst without an additional reservation transaction; each attempt records its shard and exact targets before any byte write. Freeze the catalog on first use and reject conflicting restarts, preserving retry and cleanup authority while writer isolation is validated.

This refines the earlier receipt-ID hashing draft. Online catalog expansion and rebalancing require an explicit future version transition that retains every historical target. Segmented member files remain a later change because current file identity participates in owner fencing and reclamation; adding independent existing pairs lets us test concurrency without changing that durability protocol simultaneously. See [the design](../design/storage-scaling-next-step.md) and [implementation evidence and limits](../validation/static-ingestion-shards.md); no production shard count or capacity guarantee is selected.
