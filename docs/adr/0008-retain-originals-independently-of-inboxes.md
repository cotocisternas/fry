# Retain original emails independently of inbox deletion

FRY will keep recoverable originals, including attachments, for a configurable period per organization starting at durable receipt, independently of inbox deletion; processing delays and delivery retries do not reset the clock. Expected retention is days, possibly months, with the same bounded retention-plus-grace policy for outstanding application acknowledgments, unavailable required filtering checks, and unreleased quarantine, followed by alerted expiry and a delivery-failure, processing-failure, or quarantine-expiry record as appropriate. Default/maximum durations, grace duration, and detailed expiration/recovery behavior remain open.

In the default shared IMAP mailbox, messages remain visible and usable until clients delete them, including unread messages whose original recovery-retention period has ended. Expiring retained recovery copies must not remove message bytes still needed by a live mailbox. This is a lifecycle distinction, not a requirement to store duplicate physical copies. Total mailbox storage can exceed the receipt-based recovery window. Permanent deletion does not start a new recovery period. If the receipt-based recovery period has already ended, bytes become eligible for cleanup once no other live mailbox, pending delivery, or applicable retention/grace requirement needs them. Once the final mailbox, pending-delivery/work, and recovery-retention/grace reference ends, physical removal from active storage must complete within 24 hours by default, with a configurable deadline. This is an eligibility-based cleanup clock, not a new recovery-retention period; backup/snapshot erasure is outside this answered scope. Exact deletion/expunge semantics and whether the same mailbox-lifetime policy applies to optional independent application views remain open. Existing expiry rules for pending deliveries, unavailable enabled checks, and quarantine do not authorize removing another live mailbox reference.
