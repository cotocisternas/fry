# Support self-hosted and managed cloud deployments

FRY must support multiple independent installations on self-hosted infrastructure and in the cloud using managed services, with single-region, multi-region, and on-premises topologies. Geography and data-residency constraints vary by installation. Recovery guarantees are explicit per deployment profile: resilient multi-site installations carry the no-loss/five-minute whole-site or region recovery target; single-site and single-region installations have narrower guarantees. Exact failure coverage for each profile, specific backends, and supported topologies still need evaluation.

AWS is selected for the first production rollout. Kubernetes is the preferred runtime, subject to feasibility evaluation; Amazon EKS is a candidate, not yet a selected cluster implementation. The first production rollout will use one AWS region across multiple availability zones. Whole-region-loss recovery is not a guarantee of this initial profile; the stronger multi-region profile remains later scope. The first profile must survive one entire availability-zone failure with no accepted-mail loss and restore mail reception and mailbox access within five minutes. São Paulo (sa-east-1) is the reference region; the number of zones, cluster configuration, persistence backends, and mechanisms to meet this target remain undecided; the target is not a demonstrated capability. Other self-hosted and managed deployment modes remain in scope. This is a deployment-design decision, not authorization to provision paid infrastructure.

For the first deployment and cost estimate, the user selected Brazil; use AWS South America (São Paulo), sa-east-1, as the reference region. The user does not currently have an AWS account. Consumer applications will run in a mix of AWS and external locations; the external download share is unknown. Costing must use public prices and explicit scenarios, not account-specific quotes or measured throughput claims.
