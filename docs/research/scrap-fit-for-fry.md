## Strong architectural match

SCRAP already represents the proposed replicated packed-storage approach: immutable Documents, append-only Blocks, separate byte replication and Raft metadata, derived Pebble Projection, and asynchronous Backend upload outside the ACK path. Its documented durability sequence includes local fsync, peer durability receipts, committed metadata, then visibility/ACK. Current code replicates before proposing and waits for apply before returning success. FRY could store each complete raw email as a Document while retaining SMTP envelopes and mailbox state separately. [Durability contract](/home/coto/work/dev/petabyte/scrap/CONTEXT.md:253), [write implementation](/home/coto/work/dev/petabyte/scrap/internal/shard/shard.go:503)

This does not itself atomically commit FRY's receipt, recipient ownership, and pending work. The integration still needs durable recovery between SCRAP success and FRY database commit, plus handling for lost acknowledgments. SMTP `250` must wait until both bytes and the recoverable FRY acceptance record satisfy the deployment contract.

## Concrete gaps to resolve

- **Size:** `MaxDocumentBytes` is enforced at 128 MiB. FRY's tentative 200 MB example exceeds it. Agree a maximum before reuse; splitting one original changes retrieval and atomicity obligations. [Limit](/home/coto/work/dev/petabyte/scrap/internal/store/validation.go:16), [bounded reader](/home/coto/work/dev/petabyte/scrap/internal/shard/shard.go:425)
- **Expiration:** DocumentService exposes write/head/read/find, with no Document deletion RPC; the domain explicitly forbids API deletion. Local Block eviction is not logical retention deletion. FRY's days-to-months expiry and surviving mailbox references require a lifecycle contract, tombstones, and eventual whole-Block reclamation or compaction. Backend object deletion alone would strand visible Documents. [API](/home/coto/work/dev/petabyte/scrap/proto/scrap/v1/document.proto:14), [immutability contract](/home/coto/work/dev/petabyte/scrap/CONTEXT.md:23)
- **Tenant isolation:** `tenant_id` is not part of identity or authoritative metadata. Inspected authorization checks principal roles; this is not evidence of per-Document tenant enforcement. A trusted FRY-only gateway could own authorization and globally unique storage identities; exposing SCRAP directly to organizations needs a stronger boundary. [Identity contract](/home/coto/work/dev/petabyte/scrap/CONTEXT.md:354), [authorization](/home/coto/work/dev/petabyte/scrap/internal/security/authorization.go:148)
- **Cold reads:** the accepted design explicitly restores a complete Block before serving a cold Document. Code issues `GetObject` with empty range options. This differs from the earlier selective range-GET proposal and can overfetch substantially for isolated email reads. Measure restore latency, local staging space, and cache reuse. [ADR 0027](/home/coto/work/dev/petabyte/scrap/docs/adr/0027-phase-5-restore-first-cold-reads.md:42), [restore implementation](/home/coto/work/dev/petabyte/scrap/internal/shard/restore.go:669)
- **AZ durability and degraded operation:** byte quorum is based on voter count. The inspected quorum function alone does not establish that successful copies span AZs. Review placement, volume durability, election/recovery, and FRY's explicitly permitted reduced-protection profile together. Never lower a quorum ad hoc to continue accepting. [Quorum calculation](/home/coto/work/dev/petabyte/scrap/internal/shard/replication.go:140)
- **Throughput:** `writeOrderMu` covers the per-Shard write pipeline, including append, replication, and proposal/apply. Multiple Shards may distribute work, but capacity is unmeasured. A receipt-based Transaction identity could distribute one hot inbox's bodies; mapping an inbox to one Transaction would concentrate them. [Serialization](/home/coto/work/dev/petabyte/scrap/internal/shard/shard.go:427)

## Original bytes and scanning

The gRPC API transports byte chunks and returns checksums, so opaque raw MIME is a plausible Document payload. FRY must preserve received bytes without MIME reserialization and store receipt timestamps separately from SCRAP commit timestamps. [Wire format](/home/coto/work/dev/petabyte/scrap/proto/scrap/v1/document.proto:21)

The Content Scanner is asynchronous and optional in wiring; quarantine can block Document reads. Establish how that affects IMAP consumers and original retention. It does not replace email authentication/spam policy or downstream business validation. [Scanner contract](/home/coto/work/dev/petabyte/scrap/CONTEXT.md:123), [optional wiring](/home/coto/work/dev/petabyte/scrap/internal/shard/scanner.go:62)

Conclusion: a credible storage foundation to evaluate, with retention, tenant boundaries, size, AZ recovery, and cold-read economics requiring explicit FRY integration decisions. Existing design documentation and code are evidence of mechanisms, not proof of production capacity.
