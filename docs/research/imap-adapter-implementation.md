# IMAP adapter: implementation findings

Investigated 2026-10-17 using primary source. Scope: a real-protocol shared-mailbox prototype over FRY's receipt storage, followed by the additional operations needed for conventional clients. A limited INBOX/read/flags prototype is **not** completion of [the first production milestone](../adr/0014-prove-conventional-email-first.md). This note builds on [portable storage and IMAP](portable-storage-and-imap.md); no throughput, memory benchmark, or clustered IMAP conformance result is claimed.

## Exact server boundary

Create `imapserver.New(&imapserver.Options{NewSession: func(*imapserver.Conn) (imapserver.Session, *imapserver.GreetingData, error), ...})`, then `Serve(net.Listener)`. `Options` also includes `Caps imap.CapSet`, `TLSConfig`, `InsecureAuth`, `Logger`, and `DebugWriter`. DebugWriter records credentials and mail, so leave it disabled. `Conn.NetConn()` gives the transport for cancellation or fatal literal failures. Start with IMAP4rev1 capabilities; enable extensions only when the backend implements their semantics. [Server options](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/server.go), [connection](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/conn.go).

Required `Session` methods, grouped by purpose:

| Purpose | Exact method signatures |
| --- | --- |
| Lifetime/authentication | `Close() error`; `Login(username, password string) error` |
| Selection | `Select(mailbox string, options *imap.SelectOptions) (*imap.SelectData, error)`; `Unselect() error` |
| Folders | `Create(string, *imap.CreateOptions) error`; `Delete(string) error`; `Rename(string, string, *imap.RenameOptions) error`; `Subscribe(string) error`; `Unsubscribe(string) error` |
| Enumeration/status | `List(*imapserver.ListWriter, string, []string, *imap.ListOptions) error`; `Status(string, *imap.StatusOptions) (*imap.StatusData, error)` |
| Upload | `Append(string, imap.LiteralReader, *imap.AppendOptions) (*imap.AppendData, error)` |
| Notifications | `Poll(*imapserver.UpdateWriter, bool) error`; `Idle(*imapserver.UpdateWriter, <-chan struct{}) error` |
| Retrieval | `Fetch(*imapserver.FetchWriter, imap.NumSet, *imap.FetchOptions) error` |
| Flags | `Store(*imapserver.FetchWriter, imap.NumSet, *imap.StoreFlags, *imap.StoreOptions) error` |
| Search | `Search(imapserver.NumKind, *imap.SearchCriteria, *imap.SearchOptions) (*imap.SearchData, error)` |
| Copy/deletion | `Copy(imap.NumSet, string) (*imap.CopyData, error)`; `Expunge(*imapserver.ExpungeWriter, *imap.UIDSet) error` |

`SessionMove` adds `Move(*imapserver.MoveWriter, imap.NumSet, string) error`. `SessionAppendLimit` adds `AppendLimit() uint32`. `SessionSASL` adds custom SASL mechanisms; ordinary Login does not require implementing it. Authentication failure should return `imapserver.ErrAuthFailed`. Methods have no context argument: FRY must supply bounded session/operation contexts and cancellation. [Session source](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/session.go).

## Minimum useful first prototype

Implement loopback-only authenticated access to assigned organization/inbox identities; INBOX LIST/STATUS/SELECT/EXAMINE; stable UID FETCH of complete raw mail and byte ranges; UID/size/internal date/flags; STORE set/add/remove flags; and SEARCH for UIDs, dates, headers, and flags. Keep capability claims narrow. Explicitly reject unimplemented operations and FETCH/search forms with a tagged error, rather than silently omitting requested results. This remains a compatibility subset, even though IMAP4rev1 is needed for the protocol engine.

Persist folders separately from immutable receipts: organization/inbox/folder ID, UIDVALIDITY, next UID, and ordered memberships containing UID, receipt ID, flags, and internal date. Allocate UIDs under a durable folder guard; never reuse a UID within the same UIDVALIDITY or derive it from mutable sequence positions. Preserve UIDVALIDITY across ordinary restart and assign a new value when rebuilding/recreating an incompatible mailbox identity. UID is 32-bit, so allocation needs explicit overflow handling. The durable mailbox reference must keep bytes live independently of receipt-based recovery retention. These are proposed FRY responsibilities derived from UID/mailbox semantics, not library persistence features. [UID rules](https://www.rfc-editor.org/rfc/rfc9051.html#section-2.3.1.1), [sequence numbers](https://www.rfc-editor.org/rfc/rfc9051.html#section-2.3.1.2).

`SelectData` carries `Flags`, `PermanentFlags`, `NumMessages`, `UIDNext`, and `UIDValidity`, plus legacy unseen/recent fields. `SelectOptions.ReadOnly` identifies EXAMINE. **The server itself has a TODO to prohibit mutations in read-only mode:** the backend must enforce read-only selected state and avoid implicit Seen changes. Correct CLOSE/UNSELECT behavior must also be tested; CLOSE asks the backend to expunge and then unselect, while UNSELECT only unselects. [Selection types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/select.go), [server selection](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/select.go).

## Streaming FETCH and large mail

For each matching message, call `FetchWriter.CreateMessage(clientSequenceNumber)`, then the requested `WriteUID`, `WriteFlags`, `WriteRFC822Size`, and `WriteInternalDate`. `WriteBodySection(section, exactLength)` returns an `io.WriteCloser`; stream receipt bytes into it, close it before another data item, then close the message writer. If storage fails after the literal length is announced, close the transport: emitting a tagged error into an incomplete literal corrupts framing. Still release the message writer's encoder lock on every path. [FETCH writer implementation](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/fetch.go).

`FetchOptions.BodySection` contains `*FetchItemBodySection` values: `Specifier`, MIME `Part []int`, `HeaderFields`, `HeaderFieldsNot`, `Partial *SectionPartial`, and `Peek`. A zero section selects the complete raw message; Partial has `Offset, Size int64`. Compute clipped ranges without overflow, including empty/out-of-range results. Keep full RFC822.SIZE independent of the selected range. Non-PEEK body access normally sets Seen; PEEK and EXAMINE must not. UID FETCH still reports the client's sequence number in the outer FETCH response. [FETCH types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/fetch.go), [protocol FETCH semantics](https://www.rfc-editor.org/rfc/rfc9051.html#section-6.4.5).

Do not use the sample memory backend or `ExtractBodySection` for FRY raw retrieval. That helper parses and rewrites headers, buffers the whole selected section, then applies Partial. `ExtractBinarySection` also buffers; `ExtractBodyStructure` reads single-part bodies into memory. They can multiply memory for 200 MiB messages and concurrent readers. Stream BODY[] directly from retained raw bytes; index header boundaries and bounded header metadata separately for HEADER/TEXT/search. MIME-part retrieval, ENVELOPE, and BODYSTRUCTURE need a deliberate bounded parsing/index design before claiming complete client compatibility. [Extraction helpers](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/message.go), [sample message backend](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/imapmemserver/message.go).

## Search, flags, folder mutations, and concurrent views

`SearchCriteria` combines sequence/UID sets, internal `Since/Before`, header-date `SentSince/SentBefore`, header fields, required/forbidden flags, size bounds, and nested Not/Or. Top-level criteria intersect; dates ignore time-of-day and timezone. Return a concrete `imap.UIDSet` or `imap.SeqSet` in `SearchData.All` according to `NumKind`. Never silently ignore Body/Text or unsupported criteria. `NumSet` is either UIDSet or SeqSet; zero endpoints represent `*`, so resolve dynamic ranges against the correct command snapshot instead of calling Contains blindly. [Search types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/search.go), [number sets](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/numset.go).

`StoreFlags` contains `Op` (`StoreFlagsSet`, `StoreFlagsAdd`, `StoreFlagsDel`), `Silent`, and `Flags`. Persist changes before reporting success; `.SILENT` suppresses the initiating command's flag response, not other sessions' updates. Deleted is a flag until EXPUNGE removes the membership. COPY adds destination membership with a new destination UID and another live reference. `CopyData` reports destination UIDVALIDITY and matching SourceUIDs/DestUIDs. MOVE must atomically preserve at least one live reference across destination creation and source removal; `MoveWriter` requires WriteCopyData before WriteExpunge responses. Physical receipt deletion remains a separate lifecycle decision. [STORE types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/store.go), [COPY types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/copy.go), [MOVE writer](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/move.go).

`MailboxTracker` queues EXISTS, EXPUNGE, and flag updates; each `SessionTracker` maps server/client sequence positions through pending updates and implements Poll/Idle. Respect Poll's `allowExpunge`: unsolicited expunges cannot be emitted arbitrarily during other commands. These trackers are in-memory coordination, not database locks, ownership fencing, or cross-process notifications. `EncodeSeqNum` explicitly does not handle EXISTS increments greater than one. A local prototype should serialize mailbox mutations and session snapshot changes through one coordinator, queue additions individually if using this tracker, and test simultaneous append/expunge/fetch. A distributed deployment needs fenced mailbox ownership or equivalent durable ordered changes plus catch-up. Unbounded queued updates and snapshots need capacity limits. [Tracker source](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/tracker.go), [EXPUNGE response restrictions](https://www.rfc-editor.org/rfc/rfc9051.html#section-7.5.1).

## Remaining protocol gates

APPEND defaults to 100 MiB; 200 MiB requires `SessionAppendLimit` plus matching storage admission. It receives a streaming `LiteralReader` with `Size()`, flags, and optional internal date. Source inspection also found error paths in `handleAppend` that return an earlier `err` rather than the drain or trailing-CRLF decoder error. This is an **unreproduced warning**, not a confirmed acceptance defect: test truncated literals and malformed command tails before enabling APPEND. [APPEND handler](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapserver/append.go), [APPEND types](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/append.go).

Use real loopback IMAP clients plus raw transcripts for edge cases. Gate each extension on tests for restart-stable UIDs, exact raw/partial bytes, 200 MiB bounded streaming, UID-versus-sequence behavior after expunge, concurrent shared flags, EXAMINE/PEEK, selective UID EXPUNGE, COPY/MOVE UID mapping and live references, date/header search combinations, folder rename/delete and subscriptions, large bursts, slow consumers, disconnects, and database/storage failures. Client FETCH collection helpers also buffer literals: stream the client's literal reader into a hash or bounded sink for large-message tests. Full conventional operation additionally requires the deferred core operations, credentials/TLS, deployment ownership/failover, and actual legacy-client compatibility testing. [Client streaming FETCH API](https://github.com/emersion/go-imap/blob/v2.0.0-beta.8/imapclient/fetch.go).
